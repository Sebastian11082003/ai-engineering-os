# Framework de Arquitectura

## Propósito

Establecer cómo deben diseñarse las soluciones para que sean escalables, mantenibles y alineadas con el negocio.

## Áreas clave

- Diseño orientado al dominio
- Patrones arquitectónicos adecuados al contexto
- ADRs y decisiones documentadas
- Diagramas C4, UML y de despliegue
- Diseño de APIs, bases de datos e integraciones
- Autenticación, autorización y seguridad
- Escalabilidad, disponibilidad y observabilidad
- Tolerancia a fallos y estrategia de evolución

## Relación con la documentación

Las decisiones viven como ADRs en `05-architecture/decisions/` del proyecto consumidor. El formato está en [templates/docs/_template-adr.md](../../templates/docs/_template-adr.md). Los diagramas C4/UML, el modelo de datos y los contratos de API son artefactos obligatorios de la fase de definición (ver [documentation-framework.md](documentation-framework.md)).

## Regla de oro

Toda decisión técnica debe estar justificada y documentada.
