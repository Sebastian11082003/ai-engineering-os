# Workflow

This workflow describes how work moves from idea to delivery. Documentation is not a final step: it precedes and guides implementation (SDD). See `core/modules/documentation-framework.md` and `playbooks/documentation-stage-playbook.md`.

1. Capture the request.
2. Clarify requirements, constraints, and scope.
3. Produce and validate design documentation (context, domain, product, requirements, architecture).
4. Obtain explicit authorization before writing implementation code.
5. Implement against the documented design, with tests and the same-change documentation updates.
6. Review, validate (DoD), and ship with traceability.
